# Phase 41 — Cris, the in-app IT assistant — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cris, a draggable mascot in the corner of every IT page, opens a chat box. In it, IT can:
- check a person's items;
- assign or replace a laptop by picking or scanning a spare;
- confirm and undo changes.

Every change runs through the app's existing rules.

**Architecture:**
- **Pure rules** in `src/lib/cris-*.ts`, with vitest:
  - cards, picks, placement, mood, limits, cost, undo eligibility and prompt.
- **Server code** in `src/server/cris/*`:
  - model interface (Anthropic and fake), tools, turn loop, pending actions, confirm and undo, settings.
- **Client components** in `src/components/cris/*`:
  - orb, widget and settings, mounted once in `src/app/(app)/layout.tsx`.
- **The model never writes.** It reads, or proposes a pending action. A person's Confirm runs the real lifecycle core, with `via: Cris` in the audit.

**Tech Stack:**
- Next.js 15 (App Router, server actions)
- Prisma 6 / Postgres 16
- zod 4
- `@anthropic-ai/sdk` (new dependency)
- vitest, Playwright + axe

**Spec:** `docs/superpowers/specs/2026-10-17-cris-assistant-design.md` (APPROVED 2026-10-17). It is the authority, and its UI copy is binding verbatim. The mockups are the "Cris" boards on https://claude.ai/artifact/XSKxwmMGNTvFpGHdUWujdz. CrisPage is the interactive reference for the box, cards and moods. The orb drawing and the colours are in CrisLooks.

**Limits**
- Daily: default 100 user messages per person, counted since Asia/Manila midnight.
- Rate kind `cris`: 10 per 60 s.
- Tool loop: at most 6 rounds.
- Pending actions expire after 10 minutes.
- Undo window: 60 s.
- Retention: conversations 30 days, pending actions 1 day.

**Copy (verbatim from the spec)**
- Greeting: "Hi {first name} — what do you need?" / "I can look things up and make changes. Every change waits for your Confirm."
- Hint bubble: "Hi! Need a hand? · drag me anywhere".
- Confirm card: "Check before you confirm", **Confirm {replacement|assignment}**, **Change**, and "Cris checks everything again the moment you confirm".
- Undo refusal: "Something changed since — reverse it from the record instead."
- Daily limit: "That's all my questions for today — the limit resets at midnight".
- Off: "Cris is off — no AI key is set on the server".
- Status words: Ready · Thinking… · Looking up {what}… · Waiting for your Confirm · Done.

**Sent to the model**
- Allowed: names, employee nos., titles, who they work for (including clients), tags, models, serials, holdings and gaps.
- Never: notes, free text from records, or money.

## Review Focus

1. **A person changes page mid-conversation.** The page-context person may be used only for the message sent from that page. The previous page's person is not an allowed pick afterwards. *(Task 4 test.)*
2. **Confirm is double-clicked, or Confirm is pressed on two tabs.** The second press is refused with "That's already done." and nothing runs twice. *(Task 3 test.)*
3. **The spare is taken between the card and Confirm.**
   - The refusal shows the lifecycle action's own words.
   - The result offers the remaining spares.
   - The mascot plays Frustrated.

   *(Task 3 test + Task 9 e2e.)*
4. **The provider fails or times out (no key, 5xx, a refusal stop reason).** The box shows "I couldn't reach my brain just now — try again in a moment." (refusal: "I can't help with that one."). The question is not counted against the daily limit, and the mascot plays Frustrated. *(Task 5 test.)*
5. **The 100th question and the 101st.** The 100th is answered. The 101st is refused with the daily-limit copy before any model call. The counter resets at Manila midnight, not UTC. *(Task 1 test.)*

**Interfaces (produces):**
- **`CrisCard`**, a union keyed on `type`:
  - `person {person: PersonRef; items: {assetId; tag; model; since}[]; gaps: string[]; holds: string[]}`;
  - `which {choices: PersonRef[]}`;
  - `spares {employeeId; options: SpareRef[]; offset; more: boolean}`;
  - `confirm {pendingId; kind: "assign"|"replace"; person: PersonRef; gets: SpareRef & {serial: string|null; scanned: boolean}; returns?: {assetId; tag; outcome: "DEFECTIVE"|"TRIAGE"|"MISSING"; reason: string}}`;
  - `result {pendingId; head: "Assigned."|"Replaced."; text: string; undoUntil: string /* ISO */}`;
  - `chips {items: string[]}`.
- `PersonRef = {id, name, employeeNo, worksFor, initials}`
- `SpareRef = {assetId, tag, model, typeName, warrantyEnd: string|null, backOn: string|null}`
- `CrisViewMessage = {id, role: "user"|"cris", text: string|null, cards: CrisCard[], at: string}`
- `createPending(tx, user, conversationId, kind, input): Promise<ActionResult<{ card: ConfirmCard }>>`
  - It runs `assignCore` or `replaceCore` with `{ dryRun: true }`.
  - On `ok`, it stores a `CrisPendingAction` (`expiresAt` = +10 min) and returns the card. The card is built from DB reads by id, never from model text.
- `crisConfirm(input: { pendingId: string }): Promise<ActionResult<{ messages: CrisViewMessage[] }>>`
- `crisUndo(input: { pendingId: string }): Promise<ActionResult<{ messages: CrisViewMessage[] }>>`
- `undoEligible(p: { usedAt: Date|null; undoneAt: Date|null }, touchedSince: boolean, now: Date): boolean` — true only when used within 60 s, not undone, and not touched since.

**Confirm rules** (the action runs `actionRole("admin","it_staff")` → `checkRate` → zod):
- **Refusals, in this order:**
  - not the owner → `forbidden()`;
  - used → "That's already done.";
  - expired → "That expired — ask me again.".
- The update is state-guarded: `updateMany({ where: { id, usedAt: null } })`, with count 0 meaning "That's already done.".
- It then runs the core with `{ via: "Cris" }` in the same transaction.
- A refusal from the core rolls back the `usedAt` claim and returns the core's own message. Cris then posts that message, plus a `spares` card with the remaining pickable spares.

**Undo:**
- It is a compensating change in one transaction over `prepareLifecycle` / `commitLifecycle`:
  - **assign:** the item goes to SPARE (no `returnedAt`); a hold that this assign fulfilled goes back to ACTIVE.
  - **replace:** the old item goes back to the person with its previous status; the new item goes to SPARE.
- Both are audited `lifecycle.return` / `lifecycle.assign` with `via: Cris` and the reason "Undone".
- "Touched since" means any AuditEntry on either asset created after `usedAt` other than this action's own entries.

  - `cardFromSnapshot` round-trips a confirm card.
  - A confirm card's `person.employeeNo` comes from the snapshot, not from any text field (a type test plus a value test).
