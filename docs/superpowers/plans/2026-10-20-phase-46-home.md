# Phase 46 — Overview Home and Collapsible Sidebar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every workspace's Home becomes the Overview dashboard (KPI tiles with real history, Needs you, a trend chart, make-up and breakdown), and the sidebar gains a remembered icon-rail collapse, click-to-open views, and IT-style views with counts in Purchasing, Finance and Admin.

**Architecture:**
- **History:** a nightly worker step writes per-key daily counts to a new `MetricSnapshot` table.
- **Data:** per-workspace overview builders on the server return one typed `Overview` model. Pure helpers in `src/lib/overview.ts` decide deltas, tones and weekly buckets.
- **UI:** shared React components in `src/components/home/overview/` render the model.
- **Sidebar:** the collapse is a server-read cookie, so the first paint is right. The new views and counts reuse the existing nav config, count keys and filters.

**Tech Stack:** Next.js 15 App Router, React 19, Prisma/Postgres (`prisma migrate deploy` only), Tailwind v4 tokens, vitest (node env), Playwright + axe.

**Spec:** `docs/superpowers/specs/2026-10-20-home-overview-sidebar-design.md`

## Global Constraints

- **Migration:** one new migration, `prisma/migrations/20261020090000_metric_snapshot/migration.sql`, written by hand. Apply it with `npx prisma migrate deploy` against the dev DB. Never run `prisma migrate dev/reset/format` or `db push`.
- **Tokens only, light and dark.**
  - New chart tokens: `--chart-1/2/3`, light `#2563a8` / `#eb6834` / `#1baf7a`, dark `#3987e5` / `#d95926` / `#199e70`.
  - Status colours appear only with an icon and a word.
- **Snapshot day:** the Manila calendar day. Month-to-date uses `monthStartManila`. "vs last week" for counts means live minus the value 7 days ago. For money month-to-date tiles it means this week's total vs last week's, labelled "this week vs last week".
- **No made-up history:** show "collecting history" when the comparison value is null. A sparkline needs at least 2 non-null points.
- **Every linked KPI value must equal its target page's count.** Unlinked tiles render as plain cards.
- **Cookie** `br.sidebar=rail|full` (1 year, path `/`, samesite lax). The shortcut is `[`, ignored while focus is in an input, textarea, select or contenteditable.
- **House rules:**
  - Never read or print `.env`.
  - Git: add and commit only. No stash, checkout, restore, reset, switch, amend, rebase, push, merge or clean.
  - Keep each file's line endings (Git Bash `sed -i` strips CRLF).
  - Commit trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
  - `npm run typecheck`, `npm run lint` and `npm test` must be clean before each commit.
  - **No Playwright and no dev server inside a task.** The controller runs the battery at the end.

**Interfaces:**

- **`manilaDay(now: Date): string`** returns `"YYYY-MM-DD"` in Manila. **`snapshotDue(lastDay: string | null, now: Date): boolean`**.
- **`historyFromRows(rows: { day: string; value: bigint }[], today: string): (number | null)[]`** returns 8 points for today-7·k, k = 7…0, oldest first. A missing day takes the nearest earlier row within 3 days, otherwise null.
- **`collectSnapshot(now: Date): Promise<Record<SnapshotKey, bigint>>`** reuses each live count helper (spec §2.2). **`writeSnapshot(now: Date): Promise<void>`** upserts on `(day, key)`.
- **`metricHistory(keys: SnapshotKey[], now: Date): Promise<Record<SnapshotKey, (number | null)[]>>`**.

  - `snapshotDue(null, now)` is true, the same day is false, and the next day is true.
  - `historyFromRows`: an exact day; a 2-day-earlier fill; a 4-day gap gives null; no rows gives 8 nulls.
  - `SNAPSHOT_KEYS` equals the spec's list.
- [ ] **Step 2:** Run the tests. Expected: FAIL.
- [ ] **Step 3: Implement.**

### Task 2: Overview model, pure helpers, and the IT overview

**Interfaces:**
- **Types:**
  - `KpiTile { key; label; value: number; money?: true; display?: string; href?: string; hint: string; spark: (number|null)[]; delta: Delta; upIs: "good" | "bad" | "neutral" }`
  - `Delta = { kind: "count" | "pct" | "week"; value: number } | { kind: "none" }`
  - `NeedItem { tone: "bad" | "warn" | "info"; icon: IconName; title; meta; action; href }`
  - `TrendSeries { title; unit; labels: string[]; series: { name: string; values: number[] }[] }`, at most 3 series
  - `MakeUp { title; rows: { label; value: number; tone: "chart-1" | "chart-2" | "chart-3" | "warn" | "bad" | "neutral"; href?: string }[]; money?: true }`
  - `Ranked { title; sub; rows: { label; value: number; href?: string }[]; money?: true }`
  - `Overview { kpis: KpiTile[]; needsYou: NeedItem[]; needsYouHref: string; trend: TrendSeries; makeUp: MakeUp; breakdown: Ranked }`
- **Pure helpers:**
  - `deltaTone(t: KpiTile): "good" | "bad" | "flat"`
  - `countDelta(live: number, weekAgo: number | null): Delta`
  - `weekBuckets(dates: Date[], now: Date, weeks: number): number[]` (Manila weeks ending today)
  - `sumWeekBuckets(rows: { at: Date; amount: number }[], now, weeks): number[]`
  - `weekOverWeek(buckets: number[]): Delta` (kind "week")
- **`itOverview(user: User, now: Date): Promise<Overview>`**, per spec §3.2 IT row:
  - 6 KPIs with snapshot sparks;
  - Approvals open summed over the classes `approvalClassWhere` gives this role, from per-class keys;
  - Needs you flattened from `worklist()` plus `claimedByYou()` by urgency, at most 6;
  - the trend from `AuditEntry` actions;
  - make-up from `fleet()`;
  - breakdown from a new `kitGapsByGroup(now)`.

  - `deltaTone`: up-good with +1 is good; up-bad with +1 is bad; neutral is flat; zero is flat.
  - `countDelta`: null gives `none`.
  - `weekBuckets`: Manila week edges, and an empty input gives zeros.
  - `weekOverWeek`: `[…, 10, 15]` gives `{ week, 5 }`.
- [ ] **Step 2:** Run. Expected: FAIL.
- [ ] **Step 3:** Implement the helpers and `itOverview`. KPI hrefs must be the exact list-page URLs whose counts they equal.
